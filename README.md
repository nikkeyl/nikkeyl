## Engineering principles

### Predictability

Frontend systems should be **easy to reason about**.

Data flow, state ownership, component responsibilities, and side effects should be explicit rather than hidden behind unnecessary abstractions.

### Clear boundaries

Components and modules should have **well-defined responsibilities**.

I pay particular attention to **component boundaries**, public APIs, state ownership, and the separation between UI, domain logic, and infrastructure.

### Platform awareness

**React** and **Next.js** are tools, not the foundation of the Web.

Understanding **JavaScript**, **HTML**, **CSS**, **HTTP**, browser rendering, accessibility APIs, caching, and runtime behavior leads to better architectural decisions.

### Accessibility by design

Accessibility should be part of **component architecture** from the beginning.

Keyboard interaction, focus management, semantics, validation, loading states, and error states are implementation requirements rather than final-stage improvements.

### Maintainability over cleverness

*Readable and explicit solutions* usually scale better across teams than technically impressive abstractions that are difficult to understand.

### Measured performance

Performance work should be based on **actual bottlenecks**, browser behavior, and user impact rather than assumptions.
